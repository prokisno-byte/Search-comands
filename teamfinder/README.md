# ROSTER — сайт для поиска команды

Статический сайт (для GitHub Pages) с формой заявки для игроков и кабинетом
организатора, где можно принимать или отклонять заявки. Хранилище и вход —
Firebase (бесплатного тарифа Spark хватает с запасом).

Структура:
```
index.html          — главная страница
apply.html          — форма заявки для игрока
admin.html          — вход + кабинет организатора
css/style.css       — стили
js/firebase-config.js — сюда вставляешь свои ключи Firebase
js/apply.js          — отправка заявки в базу
js/admin.js          — логика кабинета (вход, список, принять/отклонить)
```

## 1. Создай проект Firebase

1. Зайди на https://console.firebase.google.com и создай новый проект.
2. В боковом меню → **Build → Firestore Database** → «Создать базу» → режим
   **production**, любой регион.
3. В боковом меню → **Build → Authentication** → вкладка **Sign-in method** →
   включи провайдер **Email/Password**.
4. Там же, вкладка **Users** → «Добавить пользователя» — создай себе email и
   пароль для входа в кабинет организатора (это единственный аккаунт, у
   которого будет доступ к принятию заявок).
5. В настройках проекта (шестерёнка → **Project settings**) в разделе
   **Your apps** нажми «</>» (Web), зарегистрируй приложение и скопируй объект
   `firebaseConfig`.
6. Вставь эти значения в `js/firebase-config.js` вместо `"ВСТАВЬ_СЮДА"`.

## 2. Настрой правила доступа Firestore

Без этого либо никто не сможет отправить заявку, либо кто угодно сможет их
читать/менять. Зайди в **Firestore Database → Rules** и вставь:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /applications/{appId} {
      allow create: if request.resource.data.status == 'pending';
      allow read, update, delete: if request.auth != null;
    }
  }
}
```

Это значит: любой может создать заявку (со статусом «pending»), но читать
список заявок и менять их статус может только тот, кто вошёл через
Authentication — то есть ты в кабинете организатора.

## 3. Публикация на GitHub Pages

1. Создай репозиторий на GitHub, например `roster`.
2. Загрузи в него всё содержимое этой папки (сохраняя структуру `css/`, `js/`).
3. В репозитории: **Settings → Pages → Build and deployment → Source:
   Deploy from a branch**, ветка `main`, папка `/root`.
4. Через пару минут сайт будет доступен по адресу
   `https://твой-логин.github.io/roster/`.

## 4. Что можно поменять

- Название «ROSTER» и цвета — в `css/style.css` (переменные в начале файла)
  и в `<title>`/шапке каждой страницы.
- Поля формы заявки — в `apply.html` и `js/apply.js` (ключи объекта `data`).
- Если понадобится больше одного организатора — просто добавь ещё
  пользователей в Firebase Authentication, у всех будет одинаковый доступ.

## Ограничение

Кабинет организатора защищён только Firebase Auth — это нормально для
одного-двух доверенных людей, но не рассчитан на публичную регистрацию
организаторов. Ссылка на `admin.html` открыта всем, но без правильного
email/пароля попасть внутрь не получится.
